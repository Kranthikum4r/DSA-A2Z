# 40. Combination Sum II

**Platform:** LeetCode  
**Difficulty:** Medium  
**Topics:** Recursion, Backtracking, Sorting, Pick / Not Pick Pattern

## Problem Statement

Given a collection of candidate numbers (`candidates`) and a target number (`target`), find all unique combinations in `candidates` where the candidate numbers sum to `target`.

Each number in `candidates` may be used **only once** in the combination.

The solution must not contain duplicate combinations.

## Approach: Recursion (Pick / Not Pick)

We solve this problem using recursion and backtracking.

At every index, we have two choices:

1. **Pick:** Include the current element in the combination and move to the next index (`i + 1`), because each element can be used only once.
2. **Not Pick:** Skip the current element and move to the next index.

### Base Conditions

- If `sum == target`, we found a valid combination. Add the current combination to the answer.
- If `sum > target`, stop exploring that recursive path.
- If `i == arr.size()`, all elements have been processed.

### Handling Duplicate Combinations

Since the input array can contain duplicate values, the same combination may be generated multiple times.

To avoid this:

1. Sort the input array.
2. Use a loop to explore candidates starting from the current index.
3. Skip duplicate elements at the same recursion level using:

```cpp
if(j > i && arr[j] == arr[j - 1]) continue;
```

This ensures that duplicate combinations are not generated.

## C++ Solution

```cpp
class Solution {
public:
    void findcomb(int i, int sum, int target, vector<int>& cur,
                  vector<int>& arr, vector<vector<int>>& ans) {

        if(sum == target) {
            ans.push_back(cur);
            return;
        }

        if(sum > target || i == arr.size()) return;

        for(int j = i; j < arr.size(); j++) {

            // Skip duplicates at the same recursion level
            if(j > i && arr[j] == arr[j - 1]) continue;

            // Pick
            cur.push_back(arr[j]);

            findcomb(j + 1, sum + arr[j], target, cur, arr, ans);

            // Backtrack
            cur.pop_back();
        }
    }

    vector<vector<int>> combinationSum2(vector<int>& candidates, int target) {
        vector<vector<int>> ans;
        vector<int> cur;

        sort(candidates.begin(), candidates.end());

        findcomb(0, 0, target, cur, candidates, ans);

        return ans;
    }
};
```

## Example

**Input:**

```text
candidates = [10, 1, 2, 7, 6, 1, 5]
target = 8
```

**Output:**

```text
[
    [1, 1, 6],
    [1, 2, 5],
    [1, 7],
    [2, 6]
]
```

**Explanation:**

The unique combinations that sum to 8 are:

- `1 + 1 + 6 = 8`
- `1 + 2 + 5 = 8`
- `1 + 7 = 8`
- `2 + 6 = 8`

Each candidate is used at most once in a combination.

## Complexity Analysis

Let:
- `N` = Number of elements in the candidates array.
- `T` = Target value.
- `M` = Minimum candidate value.

**Time Complexity:** Exponential in the worst case due to exploring combinations. Sorting additionally takes `O(N log N)`. Output construction also requires time proportional to the total size of the returned combinations.

**Auxiliary Space Complexity:** `O(N)` for the recursion stack and current combination, excluding the output space.

## Key Learnings

- Pick / Not Pick recursion pattern.
- Each element can be selected only once.
- Sorting helps in identifying duplicate elements.
- Skipping duplicates prevents duplicate combinations.
- Backtracking using `push_back()` and `pop_back()`.
- Pruning unnecessary recursive calls.
